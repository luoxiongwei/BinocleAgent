# 项目功能清单（2026-10-23 代码审阅定稿）

> 本文基于对 agent/、tools/、scripts/、frontend/、web/、tests/ 的全量代码审阅整理，
> 描述项目**实际可实现**的功能，与代码现状一一对应。
> 架构与启动方式见 `docs/当前架构与入口.md`；技术设计动机见根目录《AGENT与YOLO融合设计.md》。

---

## 1. 项目一句话

RGB-IR 双光工地图像的「安全风险研判 + 处置分流 + 审计留痕」单 Agent：
输入一对可见光+红外图像，输出结构化风险 JSON（等级 + 条款依据 + 证据链）、
现场播报文本、审计快照与人工待审队列。

## 2. 端到端功能链路

一对 RGB-IR 图像从入库到结案的完整流程：

```
上传/入库 → 建任务(冻结输入快照) → qc 配准融合质检 → perceive VLM 场景判读(L2)
  → detect GDYOLO 检测(L1) → reconcile 双源对账 → verify_equipment 设备状态对账
  → judge 规则引擎判级+案例记忆检索 → tip/full/plan LLM 条款级判级
  → finalize 落盘终态 + 登记待审/归档队列
```

| 阶段 | 实现位置 | 功能 |
|---|---|---|
| 配准融合 | `tools/image_registration.py` + 融合脚本 | RGB/IR 标准化到统一画布(480×640)、ECC 仿射配准（仅在边缘对齐分数确有改善时采用）、融合成图 |
| L2 感知 | `scripts/vlm_judge.py` | VLM 对融合图+可见光+红外三图做结构化场景判读（人员/机械/作业状态），受 `schemas/scene.schema.json` 约束；支持 yolo_only 追问与 recrop 定向复核 |
| L1 检测 | `scripts/l1_smoke.py` + `libs/ultralytics` | GDYOLO（best.pt）对可见光独立检测 3 类目标：工人/机械/塔吊，CPU 推理 |
| 双源对账 | `tools/reconcile.py` | 纯几何对账：matched / vlm_only(打 unverified_by_yolo) / yolo_only(触发 VLM 追问) |
| 设备对账 | `tools/evidence_tool.py` 相邻逻辑 + `graph.verify_equipment` | 工人框⊆机械框几何校验 × VLM 设备状态交叉验证 |
| 判级 | `tools/rule_engine.py` + `scripts/llm_judge.py` | 规则引擎（作业类型×安全防护×监督陪护三要素）给**等级下界**；LLM 经 RAG 混合检索（BGE 向量 + BM25 + RRF + 精排，9 部 JGJ/GB 规范）生成条款级判级，强制不得低于下界，报告经幻觉校验（引用的 bbox_id/条款必须真实存在） |
| 处置分流 | `agent/outcome.py` | 终态三分类 → 四处置通道（见 §3） |
| 审计留痕 | `graph_state.json` / `events.jsonl` / `checkpoint.sqlite` | 每任务独立状态快照 + 事件流 + 断点恢复 |

## 3. 判定语义（处置四通道）

| outcome | 含义 | disposition | 转人工 |
|---|---|---|---|
| `judgement_success` 高风险 | 判出高危 | `P1_auto_alert` 强制告警 | 否 |
| `judgement_success` 低风险 | 判出低危 | `TIP_optional` 可选提示 | 否 |
| `judgement_success` 安全 | 判为安全 | `P4_archive` 安全归档（进抽样复核） | 否 |
| `judgement_failed` | 判不了但原因可定位（有 reason code） | 自主结案 + 抽样复核 | 否 |
| `undecidable` | 判不了且无法归因 | `P3_manual_judge` 转人工 | **是（唯一）** |

判定铁律（代码已落实）：
1. 有等级必有处置，禁止"判了等级又转人工"
2. 有危险必须告警——条款是追责依据非告警前置，高危无条款照常 `P1_auto_alert` 并记 `clause_support_missing`
3. 感知链失效（VLM 降级/零目标）不得判"安全"，必须走人工闸口（`R-PERCEPT-DEGRADED`）

## 4. 服务 API 能力

### agent.service（:8000，生产任务服务）
| 端点 | 功能 |
|---|---|
| `POST /tasks` | 创建后台研判任务（pair_id 支持规范 ID 或中文别名；冻结输入快照） |
| `GET /tasks/{id}` | 状态快照（checkpointer + 磁盘状态合并，含证据链） |
| `GET /tasks/{id}/events` | 任务事件流（JSONL，前端实时时间线数据源） |
| `POST /tasks/{id}/retry` | 失败任务重试（上限 2 次） |
| `POST /tasks/{id}/review` | 专家 verdict 回写（接受/修改/驳回） |
| `POST /tasks/{id}/acceptance` | 人工验收（accept/correct/reject，写案例记忆） |
| `GET/POST /tasks/{id}/feedback`、`GET /feedback/*` | 用户反馈与离线校准候选（≥3 条同类错误才出候选，不自动改规则） |
| `POST /inputs` / `GET /inputs` / `POST /inputs/rename` | 图对上传（自动分配 pairNN + 中文别名，替换语义）/ 查询 / 重命名 |
| `POST /chat`、`GET /chat/tools` | 统一对话入口（AgentLoop 工具循环 + 专家注册表 + 8 个 function-calling 契约） |
| `POST /qa/ask`、`GET /qa/sessions/{id}` | 规范知识问答（本地 RAG 检索 + 会话管理，可绑定到任务） |
| `GET /batches`、`GET /policy/version`、`GET /memory/cases`、`GET /health` | 批次/策略版本/案例记忆/健康检查 |

### agent.api_web（:8010，只读控制台）
- 读：总览 KPI、验收批次、任务归档、图对图片、待审队列、人工档案、金标集、案例记忆
- 唯一写操作：`POST /pending/{task_id}/resolve`（标记待审已处理）
- 不触发任何模型调用——**无 key 也能查历史与队列**，适合部署给安全督查岗

## 5. 前端能力（Vue3 主控制台，:5173）

| 页面 | 组件 | 功能 |
|---|---|---|
| 落地页 | LandingView | 入口页，跳转安全日志 |
| 安全日志 | TaskWorkspace（双 Tab，问答在前）+ TaskView + ConversationWorkspace | **智能问答**（默认）：多轮对话工作区（session 绑定任务，对话中发起的任务自动跳转到研判页并加载）；**研判任务**：上传双光图对（支持中文名）→ 流水线实时事件时间线（1s 自动观测轮询）→ 安全日志 + 证据链三联图 + 反馈/验收 |
| 工作总览 | ConsoleView | KPI 4 卡（待人工复核/强制告警/研判完成/在线研判）+ 处置分布 + 服务状态 + 最近研判任务下钻 + 离线人工归档。**不展示验收批次**（金标集只覆盖 30 对实验数据，对交付受众不可达，2026-10-19 决策） |
| 人工复核 | ReviewDesk | 待审队列按日期分组，接受/修改/驳回并回写风险等级 |
| 档案管理 | BatchView | 双 Tab（实时任务流 / 历史日志），隐藏式日历选日，双栏布局 |

全局能力：顶栏注释总开关（`localStorage.gdyolo-notes-visible`）、30s 自动轮询、服务健康灯、待审计数徽标。

### 零依赖只读控制台（web/console.html，8010 `/console` 挂载）
单文件 46 KB、无构建步骤。7 个视图：总览 / 批次评估 / 图对详情 / 待审队列 / 专家真值集 / 作业类型记忆 / 服务与词表。
与 Vue 前端**互补不替代**：它面向验收/审计场景（批次评估、真值集、记忆沉淀是 Vue 端没有的），无任务发起与上传。

## 6. 批量验收与闭环工具（CLI）

## 8. 规划器（可开关的有界自主性）

`agent/planner.py`（`config/agent.yaml` 的 `planner_enabled` 开关）：
- 种子链路（qc→perceive→detect→reconcile→verify→judge）**确定性执行**，LLM 不插手
- 仅在 tip/full/manual 分支给 LLM 有限自主权（白名单 3 工具：generate_judgement / request_human_review / finalize_plan），有界 ReAct
- 规则引擎等级是下界，LLM 不可绕过代码侧处置推导
- 对账失败时可走 `plan` 节点做定向重感知
